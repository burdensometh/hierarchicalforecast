# 滚动留出协调器选型流程（基于非对称缺货成本）

本目录是一套可运行的参考实现，替代运营团队过去“按平均误差（MAE/RMSE）挑选预测方法，
直到重点区域缺货成本超预算”的做法。

| 文件 | 作用 |
| --- | --- |
| `cost.py` | 非对称分段线性缺货成本（即 pinball / 分位数损失），支持按序列单位成本与层级权重汇总 |
| `rolling.py` | 滚动原点留出选型主流程、候选管线定义、共同支撑集配对比较 |
| `demo.py` | 端到端可运行示例：合成层级 + 三个协调器候选 + 迟到候选演示 |
| `../tests/test_rolling_selection.py` | 单元测试（成本语义、标签映射、预算约束、防切换、共同支撑集） |

## 1. 为什么不能再用平均误差选方法

MAE/RMSE/MAPE 是**对称损失**：少预测一个单位和多预测一个单位代价相同。
库存场景下两者并不对称：

- 少预测（under-forecast）→ 缺货 → 失销毛利、合同罚款、加急运费，单位代价 `c_under`；
- 多预测（over-forecast）→ 持有/减值成本，单位代价 `c_over`。

本实现对序列 *i* 的每期成本为

```
L_i(y, ŷ) = c_under_i · max(y − ŷ, 0)  +  c_over_i · max(ŷ − y, 0)
```

单位成本恒定时它恰好是分位数水平 `τ = c_under / (c_under + c_over)` 下的
pinball 损失，因此最优点预测是服务水平分位数而非条件均值。重点区域通过其**真实经济
代价**（更高的 `c_under`）进入目标函数，而不是在选出方法之后再用预算去否决——预算约束
仍然保留（见第 4 节），但它是护栏而不是选型目标。

### 层级权重如何汇总

`AsymmetricStockoutCost.score` 的汇总约定（与库内 `evaluation.evaluate` 的
“先序列内聚合、再层级聚合”口径一致）：

1. 逐 (序列, 期) 计算成本；
2. 在留出期内对时间取均值，得到每条序列的每期平均成本；
3. 每个层级内部用 `series_weights`（层级内归一化）加权汇总；
4. 各层级用 `level_weights`（归一化到和为 1）汇总为单一可比标量。

预算报表另走 `monetary_total()`（未归一化的总金额）与 `stockout_component()`
（仅缺货部分金额），回答“这个候选在留出期实际烧掉多少钱”，与选型标量区分开。

## 2. 滚动留出流程（每个切点严格无泄漏）

设历史为 `Y[:, 0:T]`，切点位置为 `t`，预测步长 `h`：

```
for t in cutoffs:
    1. 切出训练前缀 Y[:, :t+1]；t+1 之后的数据对本切点完全不可见。
    2. 对每个候选管线（基础预测器 + 协调器）：
       a. 仅用该前缀【重新拟合基础预测器】，产出留出期预测 Ŷ_h 与样本内拟合值；
       b. 用同一前缀【新建并拟合一个全新的协调器实例】
          （BottomUp / TopDown / MinTrace / ERM …），得到协调预测；
       c. 在实现值 Y[:, t+1:t+1+h] 上计算非对称成本，记录得分与支撑集。
    3. 按选型规则选出胜出方法（含预算与防切换护栏，见第 4 节）。
    4. 用胜出方法在完整前缀上【再拟合一次】，发布下一期（第一步长）预测。
    5. 滚动到下一个切点。
```

关键的无泄漏约束，代码中均有强制：

- **基础预测器逐切点重拟合**。`Candidate.forecast_fn` 只接收前缀数组，
  看不到留出期；超参数搜索也必须在该前缀内部完成。
- **协调器逐切点新建实例**。库内协调器会把拟合出的投影矩阵 `P`、`W` 存在实例上
  （`methods.py`），复用实例会把旧参数带到新切点，因此 `make_reconciler`
  被定义为零参数工厂，每次返回未拟合的新对象。
- **需要样本内数据的方法**（如 `MinTrace(method="mint_shrink")`）接收的
  `y_hat_insample` 同样只由前缀产生，不能用全样本残差估计协方差。
- 切点合法性有校验：每个切点之后必须留有完整 `horizon` 期实现值，否则直接报错。

### 两种选型规则

- `per_cutoff`：只看当前切点的成本，噪声大、方法切换频繁，仅建议在切点很多时使用。
- `cumulative`（默认、推荐）：用截至当前所有切点的累计平均成本决策，证据逐期累积，
  并配合 `min_switch_gain`（相对改善阈值，如 2%）抑制无意义的方法抖动。
  首个切点没有历史证据时默认留任现任方法（`incumbent`），不凭单期噪声切换。

## 3. 候选覆盖不同序列日期时，为什么不能直接比较

这是本流程显式处理的核心问题。两个候选若覆盖的 (切点 × 步长 × 序列) 单元格不同
——新方法上线晚、某数据源历史更短、某些区域无法产出预测——直接比较它们的平均成本
是无效的，原因有三：

1. **难度不同期，分数不可比。** 库存误差有强烈的时变性（促销期、季节峰、供应中断期）。
   候选 A 只在平稳期有预测、候选 B 覆盖了促销高峰，即便 B 的方法更好，其均值也会更高。
   分数差异混淆了“方法差异”和“评估窗口差异”两个因素。
2. **均值的分母不同，数学上不在同一测度上。** 一个在 20 个单元格上平均、另一个在
   50 个单元格上平均，两个标量不存在“谁低谁优”的偏序关系；用全表 `mean(skipna=True)`
   排名会系统性偏向覆盖期更平稳的候选。
3. **会制造针对缺口的套利。** 若某候选可以选择只在容易的时段产出预测，直接按均值奖励
   它，等于奖励“挑软柿子”，而不是奖励预测质量。

**正确做法：在共同支撑集（support intersection）上做配对比较。** 实现中每个候选在
每个切点都记录布尔支撑掩码 `support`（哪些步长对全部序列有效）；覆盖期较短的候选可通过
`Candidate(entry_cutoff=k)` 声明其首个可用切点——在那之前它根本不参与拟合与评分，
缺失是结构性的而非伪造的 NaN。`common_support_score(records, A, B)` 只对 A、B **同时**
产出预测的单元格取成本再比较，累计排行榜同样按候选各自实际覆盖的切点累计，
缺失历史不参与、也不惩罚。`demo.py` 末尾构造了一个从后半段切点才进入的迟到候选，
并断言配对比较只使用重叠切点的单元格。

注意取舍：共同支撑集保证了比较的**内部有效性**，但覆盖范围本身也是运营价值——
一个只能覆盖 30% 区域的方法不应仅凭低分中标。因此审计输出同时保留覆盖率信息
（支撑掩码、逐切点得分表），覆盖率门槛应作为与成本并列的准入条件，由业务侧显式设定，
而不是悄悄并入一个均值。

## 4. 预算与护栏

- `stockout_budget`：留出期**仅缺货部分**成本的上限。超预算候选即使总分最低也不能胜出；
  若所有候选都超预算，则选缺货成本最小者并保留可审计的超限事实（不能假装预算没破）。
- `min_switch_gain` + `incumbent`：累计证据相对现任的改善达不到阈值（默认 2%）则不切换，
  避免方法在噪声边界来回抖动带来的流程成本。
- 选型标量（层级加权平均成本）与预算金额（未归一化总额）分开报告，
  避免“加权平均没超、重点区域总额已超”的口径混淆。

## 5. 如何接入真实管线

1. 用 `hierarchicalforecast.utils.aggregate` 得到 `Y_df, S_df, tags`，
   按行序保存 `unique_id`（滚动函数需要 `series_labels` 把标签 tags 映射为位置索引，
   与库内 `core.py` 的处理一致）。
2. 把 `Candidate.forecast_fn` 换成真实基础预测器（statsforecast / mlforecast /
   neuralforecast 均可）的**前缀内重拟合**工厂，并同时返回样本内拟合值供
   协方差类协调器使用。
3. 用财务侧的单位缺货/持有成本构造 `AsymmetricStockoutCost`，
   用层级管理权重构造 `level_weights`。
4. 运行 `rolling_holdout_selection`，审查 `leaderboard()`、`winners()`、
   `cumulative_paired_scores()` 与共同支撑集配对结果。
5. 生产发布只取每个切点 `record.published`（胜出方法重拟合后的下一期预测），
   其余数据留作审计与回溯。
